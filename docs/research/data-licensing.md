# Data Licensing & Terms Research

PermitGraph deliberately uses **four different license regimes** for four different
kinds of content in this repository. Never assume one license applies to all of it.

## 1. Code license: Apache License 2.0

All source code in `apps/`, `packages/`, `cli/`, `scripts/`, `tests/`, `infra/`,
`docker/` is licensed **Apache-2.0** (see `/LICENSE`). Apache-2.0 was chosen over
MIT because it includes an explicit patent grant and contribution-license terms,
which matter for an infrastructure project aimed at government-adjacent, commercial,
and non-profit adopters alike, and is the de-facto standard for regulatory/compliance
infrastructure projects referenced in `open-source-landscape.md` (Catala, Temporal).

## 2. Government source documents (the three uploaded Acts)

**Legal basis:** Section 52(1)(q)(i)–(ii) of the Copyright Act, 1957 provides that the
reproduction or publication of **an Act of a Legislature** is *not* an infringement of
copyright, including when reproduced together with commentary or other original matter.
([Source](https://indiankanoon.org/doc/1013176/)) This is why bare-acts aggregator sites
(IndiaCode itself, PRS Legislative Research, LatestLaws, LegitQuest, BareActsLive, etc.)
are able to republish full statute text freely.

**What this means for PermitGraph:**
- The **plain text of the Acts** (Maharashtra Industrial Development Act 1961, the
  Maharashtra Industry, Trade and Investment Facilitation Act 2023, and the Maharashtra
  — formerly "Bombay" — Khadi and Village Industries Act 1960) can be stored and
  redistributed in this repository as statute text, with source attribution.
- **Government-prepared commentary, departmental circulars, internal SOPs, or
  copyrighted secondary material are NOT included** — only the enacted statute text
  itself, retrieved from official/primary repositories (`indiacode.nic.in`,
  `cdnbbsr.s3waas.gov.in`) and cross-checked against PRS India's legislative archive.
- Original PDF **scans themselves** (page images) are treated conservatively: we do not
  bulk-redistribute large binary scans of record in this repository. We store **hashes,
  structured extracted text, and page/section references**, consistent with
  `README`/`docs/architecture` guidance to keep large binaries out of git. If/when the
  actual scanned source PDFs (as referenced in the project brief) are added to the
  workspace, the OCR pipeline in `packages/document-engine` is designed to ingest them
  directly, and only their extracted text + hash + page provenance would be committed,
  not the raw scan.
- **This repository's authoritative-source text is NOT the Official Gazette** — it is a
  reproduction for engineering/demo purposes. For any real-world legal reliance, users
  must consult the Official Gazette / india code / the issuing department directly.
  PermitGraph's README and API responses carry this disclaimer.

## 3. Extracted factual metadata & rules-as-code derived from the Acts

- Structural facts that are **direct transcriptions** of the statute (e.g., "Section 14
  establishes MAITRI as the Nodal Agency") are stored as `verification_status=candidate`
  until a qualified human reviewer confirms the transcription, then may be promoted to
  `verified`. See `docs/PROJECT-RESEARCH.md` §15 and `packages/rules-engine` for the
  verification workflow — **the AI agent that built this repository does not self-verify
  legal content as a final authority.**
  AI-authored candidate rules are licensed the same as code (Apache-2.0) once published
  as rules-as-code YAML, since they are original structuring/engineering work over
  public-domain-reproducible statute text, not new legal content.
- We do **not** claim copyright over the statute text itself (it has none, per §2 above);
  we do claim normal code copyright over the YAML/JSON *structuring* of that text.

## 4. Synthetic data

All files under `data/synthetic/` (businesses, documents, workflow events, regulatory
change scenarios, approval graphs) are **wholly generated by this project's seed
scripts** (`scripts/generate_synthetic_*.py`), contain no real personal data, no real
business data, and no scraped third-party dataset content. They are released under
**CC0 1.0 Universal (Public Domain Dedication)** — maximally reusable for research,
benchmarking, and downstream tooling, with an explicit `synthetic: true` flag baked
into every record so it can never be confused with `data/real/`.

## 5. Candidate / AI-inferred data

Files under `data/candidate/` are **not licensed for reliance** — they are explicitly
marked `verification_status=candidate` or `UNVERIFIED`, are excluded from any "verified
corpus" claim, and are provided only to make the human-review workflow inspectable and
testable. Treat them the same as code license-wise (Apache-2.0, since it's our
engineering artifact), but **never treat their content as fact**.

## 6. Third-party portal terms (NSWS / MAITRI / MIDC / PARIVESH)

No content, screenshots, data exports, or API responses from NSWS, MAITRI, MIDC, or
PARIVESH are reproduced in this repository. All descriptions of those systems in
`docs/research/government-landscape.md` are summaries of publicly available
press-release and news material, with citations, for research/comparison purposes
only (fair-dealing-style use for criticism/research commentary) — not data
redistribution. PermitGraph does not scrape, mirror, or claim API access to any of
these live government systems.
