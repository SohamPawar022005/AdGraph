# Synthetic Dataset

Generated by [`scripts/generate_synthetic_dataset.py`](../../scripts/generate_synthetic_dataset.py)
(seed `42`, fully deterministic/reproducible). See `MANIFEST.json` in this directory
for exact counts and generation timestamp of the copy currently on disk.

## What this is

**100% synthetic.** No real businesses, applicants, officers, uploaded documents, or
regulatory amendments are represented anywhere in this directory. Names, numbers, and
text here are randomly generated for load-testing, demo, and benchmark purposes only.

This directory corresponds to the `synthetic` data tier (`shared.DataTier.SYNTHETIC`)
and is kept strictly separate from `data/real/` (authoritative Act text) and
`data/candidate/` (AI-extracted rules pending human review) — see
`docs/research/data-licensing.md` and the repository root `data/README.md` tier
policy. Per that policy, synthetic data does **not** require human regulatory review
before use (unlike `data/candidate/`), because it carries no claim of legal accuracy.

## Contents

| File | Approx. count | Purpose |
|---|---|---|
| `businesses/businesses.jsonl` | 5,200 | Synthetic `BusinessProfile` records across 14 illustrative industry categories and 20 Maharashtra districts, with MSME-like investment/employee scale bands (micro/small/medium/large). |
| `workflow/applications.jsonl` | 5,300+ | Synthetic permit applications, each tied to a business and an approval from the demo approval catalogue. |
| `workflow/events.jsonl` | 14,000+ | Workflow state-transition events, generated by **random-walking the real deterministic FSM** in `packages/workflow-engine` (not hand-scripted outcomes) — so the event log is guaranteed to only contain transitions the real engine considers valid. |
| `documents/documents.jsonl` | 1,300 | Document ingestion plans (type + synthetic extracted-field payloads, ~80% deliberately well-formed / ~20% deliberately missing required fields) for exercising the real `document_service.validate_document` deterministic validator at load time. |
| `changes/regulatory_change_scenarios.jsonl` | 120 | Synthetic old/new section-text pairs spanning every `ChangeType` (deadline, threshold, authority, document-requirement, applicability, definition changes), attached to a dedicated `SYNTHETIC-SCENARIO` pseudo-document — never confused with the 3 real source Acts. Used to exercise the real change-detection + impact-analysis engines, not to pre-bake their output. |
| `graphs/approval_graphs.jsonl` | 520 | Per-business approval-dependency subgraphs (nodes + edges) derived from the same approval catalogue loaded by `scripts/seed_real_corpus.py`, for graph-engine benchmarking/regression fixtures. These are **derived fixtures**, not a new "saved graph" product feature — PermitGraph always computes a business's live dependency graph on demand via `graph_service`. |

## Loading into the dev database

```bash
python scripts/generate_synthetic_dataset.py   # (re)generate the fixtures above
python scripts/load_synthetic_dataset.py       # load them through the real service layer
```

`load_synthetic_dataset.py` inserts businesses/applications/events directly (bulk,
`is_synthetic=True`) but routes documents through `document_service.ingest_document` +
`validate_document`, and routes regulatory-change scenarios through
`change_service.analyze_and_persist` + `impact_service.run_impact_analysis` — so the
*demo data* and the *real pipeline code* are both exercised together, rather than the
loader just writing pre-computed "fake" results into the database.

## What this is explicitly NOT

- Not a statistically representative sample of Maharashtra's actual industrial base.
- Not a source of real regulatory deadlines, authorities, or thresholds — the
  `changes/regulatory_change_scenarios.jsonl` text is invented for engine testing and
  must never be cited as evidence of an actual amendment.
- Not eligible for human regulatory review promotion — synthetic records stay
  `is_synthetic=True` / `SYNTHETIC` forever; they are a parallel track to the
  real → candidate → verified pipeline, not a shortcut into it.
